LEADERSHIP DEMO · 3 MIN

Foundry + Windows 365
Computer-Use Agent

An end-to-end agent that operates a real Windows desktop — what it takes to build today, and where native integration removes the tax.

THE QUESTION

Not "can a customer build this" — how hard is it?

"We already know a customer can build an end-to-end computer-use agent on Foundry and Windows 365 — that's not in question. What we wanted to understand is how easy or hard that actually is today, and where Microsoft has a real opportunity to close the gap with native integration."
THE SCENARIO

One instruction. A real desktop. A human watching.

A Foundry-hosted agent opens a browser on a real Windows 365 Cloud PC, reads an invoice visually off the screen the way a person would, and writes a structured summary into Notepad — with a live, authenticated viewer link a human can watch or take over at any time.

WHAT IT TOOK · PART 1
0:25 – 1:10

Identity was the biggest piece of engineering

"Think of it like getting a visitor badge for a secure building, except you need three badges, one after another — each one only gets you the next. The agent's own credential gets badge one. We hand that back to Microsoft Entra and get badge two: proof this is a real agent identity. Hand back both, and we get badge three — the only one Windows 365 actually lets through the door. We had to build that whole handoff ourselves."
"And it's not just badges. We also had to set up a dedicated W365 user account for the agent, license it, and put it in the right Cloud PC pool — separate from the agent's own identity. Three things to register and wire together before any badge handoff even starts."
WHAT IT TOOK · PART 2

Three things to set up, one badge handoff

Connecting to the desktop tools

We attach the final badge to every call to Windows 365, and check what desktop actions are available fresh each session — nothing hardcoded.

Keeping the session safe

We track who owns a session before we start it, so a flaky start never leaves an abandoned or duplicate desktop. If anything comes back unclear, we treat it as unresolved — never as success. Always cleaned up.

Honest caveat

We wanted this to run on the agent's built-in identity alone, no stored secret. One handoff step hit a limitation on the Microsoft Entra side, so we added a plain fallback just for that step. A stopgap, not the design we actually want.

THE ASK

Make the plumbing a platform guarantee

"If Windows 365 becomes something Foundry supports out of the box — where Foundry does that badge handoff for us and sets up the W365 user account automatically, the same way it already smooths over other tool connections — most of that identity setup just goes away. What's left is the actual business logic and the safety checks around the desktop session, which we'd want to keep either way.

It works today. It's just more plumbing than a customer should have to build themselves — and that's a solvable gap for the platform to close."
